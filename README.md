# PMS Manager

PMS 요청내용·이미지와 로컬 프로젝트 소스를 연결해 원인 후보와 수정 방향을 분석하는 Windows PC 프로그램입니다.

## 실행 순서

`release/PMS-Manager.exe`를 실행하세요. 별도 Node.js 설치가 필요하지 않습니다. 실행파일 이름은 앞으로도 동일하게 유지합니다. 업데이트할 때 기존 프로그램을 종료한 뒤 같은 파일을 교체하세요. 버전과 변경 사항은 `CHANGELOG.md`에 기록합니다. 기존 버전별 실행파일은 `release/archive`에 보관합니다. 변경일: 2026-10-16, 작성자: 김기덕. 상세 변경은 `REVIEW-2026-10-16.md`, 실제 실행에서 발견한 원인은 `TEST-2026-10-16.md`를 참고하세요.

1. **프로젝트 · AI 설정 → 폴더 등록**에서 `icms` 같은 프로젝트 최상위 폴더를 선택합니다. 모든 하위 폴더를 재귀적으로 살펴보고 지원하는 텍스트 소스의 내용을 검색합니다. 프런트엔드와 서버가 서로 다른 루트에 있으면 두 폴더를 모두 등록하세요.
2. **AI 계정 연결**에서 **ChatGPT 플랜 · 로그인으로 연결 → Continue with ChatGPT**를 누릅니다. 열린 브라우저에서 직접 로그인하고 이 앱의 플랜 사용 권한을 승인하세요. 프로그램으로 돌아와 **연결된 계정으로 모델 목록 조회** 후 모델을 선택하고 **연결 설정 저장**을 누릅니다. 계정·워크스페이스가 지원하지 않거나 사용 한도에 도달하면 안내를 확인하세요. **ChatGPT 사용량 관리**에서 한도와 접근 권한을 관리할 수 있습니다. 기존 방식은 **OpenAI · API 키로 연결** 등 제공업체를 선택해 사용합니다. API 키는 별도 API 크레딧을 사용하며, 두 방식 간 자동 과금 전환은 없습니다. 변경일: 2026-10-16, 김기덕.
3. **PMS 열기**로 연 프로그램 전용 PMS 창에서 직접 로그인합니다. 기존 Chrome 창의 로그인·조회 상태를 가져오는 방식은 아닙니다.
4. 상단 **프로젝트관리**, 왼쪽 **공정관리 → 테스트단계 → 바로콘변경요청관리**에서 검색조건을 직접 입력하고 **조회**합니다. 필요한 단위시스템을 선택해 요청내역 목록까지 표시하세요.
5. 앱에서 **PMS 로그인과 검색조건 입력·조회를 완료했습니다**를 체크하고 **신규·변경 내용 자동 분석**를 누릅니다. 수집 중에는 PMS의 검색조건이나 선택 행을 변경하지 마세요.
6. 프로그램이 요청ID 셀을 하나씩 선택합니다. 각 요청마다 상세 본문과 이미지를 읽어 즉시 저장하고, 신규·변경·미분석 내용이면 하위 소스 검색과 AI 분석까지 완료한 뒤 다음 행으로 넘어갑니다. 본문 관찰과 이미지별 관찰, 수정 대상 소스와 해결 절차를 나누어 표시합니다. 다음 조회 후 같은 버튼을 누르면 동일 내용은 건너뜁니다.
7. 요청별 결과·이미지·소스 발췌를 검토하고 메모와 검토 상태를 저장합니다. **보고서 저장**으로 선택 요청의 Markdown 보고서를 내보냅니다.

프로그램은 PMS 요청ID 셀을 순차 선택해 상세를 읽습니다. PMS의 저장·삭제·상태 변경 또는 소스 자동 수정을 실행하지 않습니다.

## 실시간 작업 현황과 보완 대화

- **실시간 작업 현황**에서 목록 탐색 → 상세·이미지 수집 → 내용 비교 → 하위 소스 색인 → 관련 코드 검색 → AI 응답 대기 → 결과 저장을 확인합니다. 현재 단계의 처리 건수·진행률, 전체 분석 대상 처리 건수, 경과 시간을 표시합니다. 전체 건수를 아직 모르는 폴더 탐색과 AI 응답 대기는 불확정 진행 상태로 표시합니다.
- **이번 작업 요청**은 수집한 목록의 요청ID·제목과 수집 대기/분석 대기/진행/완료/생략/실패 상태를 보여줍니다. 진행 중인 요청을 강조하며, 수집 결과가 저장된 후 해당 항목을 누르면 상세를 열 수 있습니다. 분석 결과는 요청별 저장이 끝날 때 갱신됩니다.
- **실시간 작업 터미널**에는 시간·단계·요청ID가 포함된 최근 500개 로그가 표시됩니다. 새 로그 따라가기를 끄면 이전 로그를 읽을 수 있습니다. 작업 목록과 터미널은 접거나 펼칠 수 있습니다. 로그는 현재 실행 세션에서 유지되며 새 작업을 시작하면 초기화됩니다.
- 요청 상세와 수정 방향 **오른쪽의 함께 보완하기**에서 추가 재현 조건이나 질문을 입력합니다. 저장된 AI 제공업체·모델을 사용하며 요청 본문·이미지·연결 소스·기존 분석·검토 메모와 최근 대화 20개를 함께 전송합니다. 분석 중에도 이미 수집한 요청에 대해 대화할 수 있습니다.
- 대화는 요청별 최근 100개 메시지를 저장하며 재수집 후에도 유지합니다. 요청 전환 시 초안을 유지하고, 오류·중지 시 입력을 남겨 다시 전송할 수 있습니다. **Ctrl+Enter**로 전송하고 **답변 중지**로 대화만 중지합니다. 분석의 **작업 중지**는 별도로 동작합니다.
- 이번 버전부터 분석에 사용한 소스 발췌도 함께 저장해 재실행 후 대화에 사용합니다. 구버전 결과 등 소스 발췌가 없는 요청에는 **소스 미연결**을 표시합니다. 대화는 소스를 자동으로 수정하지 않으며, 기존 분석 보고서는 유지하고 보완 대화를 별도로 저장합니다.

## 동일 내용 생략

- 같은 요청ID별로 본문과 이미지 바이트의 해시를 저장합니다. 목록 순서·제목·처리상태·등록일 변경만으로 다시 분석하지 않습니다. 줄바꿈 방식과 줄 끝 공백 차이는 무시합니다.
- 성공한 내용 해시는 재실행 이후에도 유지합니다. 예전에 분석한 내용으로 돌아온 경우도 재호출하지 않으며, 최근 5개 이력에 해당 보고서가 있으면 복원합니다.
- 본문 또는 이미지가 달라지면 다시 분석합니다. 이미지 누락·상세 로딩 실패는 동일 내용으로 간주하지 않고 확인 필요로 표시합니다.
- 요청내용이 같으면 소스나 모델 설정만 변경해도 재분석하지 않습니다.
- 실행 시 현재 PMS 조회 목록을 읽습니다. 주기적인 자동 조회는 하지 않으므로 검색 결과 갱신은 PMS의 조회 버튼으로 진행하세요.

## 소스 연결

`REQ-ec/ecg/ECG0502.xfdl36` → `ec/ecg/ECG0502.xfdl`

- 2026-10-16 김기덕: 등록 폴더의 하위 **파일 경로 목록**을 먼저 파악합니다. `ECC0101`이면 대소문자에 관계없이 `EC/ECC` 폴더의 내용을 색인합니다. 요청 본문에 등장하는 화면 파일, 소스에서 명시적으로 참조하는 include·클래스 파일을 추가하고 같은 범위는 실행 중 재사용합니다.
- 업무 폴더를 찾지 못하면 상위 업무 폴더, 경로가 전혀 맞지 않으면 등록 폴더 전체로 확대하며 화면에 이유를 표시합니다. 업무 폴더 밖의 파일명이 다른 동적 API·SQL 연결을 자동으로 모두 찾는 방식은 아니며 추가 확인이 필요합니다.
- 기준 파일이 없어도 관련 내용이 있는 다른 소스에서 분석을 시작합니다. 중복 기준 파일은 최대 8개 후보를 함께 표시하고 실제 배포 경로 확인이 필요하다는 경고를 남깁니다.
- 내용 검색 결과에서 함수 호출·선언, 클래스·import, API 경로, MyBatis namespace/statement ID, SQL 테이블, 파일 include를 찾아 **최대 5단계**까지 반복 검색합니다. 단순한 Spring 클래스·메서드 경로 조합도 인덱싱합니다.
- 예: 화면 XFDL → 다른 이름의 컨트롤러 → 서비스 메서드 → 파일명이 다른 매퍼 XML → 테이블 DDL. 각 파일의 선정 이유와 검색 경로를 화면에 표시합니다.
- 연결 관계는 문자열·선언 일치에 기반한 **후보 관계**입니다. 동적 SQL, 런타임 생성 경로, DI, 리플렉션 등을 완전히 해석하는 컴파일러 수준의 호출 그래프는 아닙니다. AI가 제공 소스를 대조하고 확인할 수 없는 연결은 별도로 표시하도록 요청합니다.
- UTF-8·EUC-KR·BOM이 있는 UTF-16을 지원합니다. XFDL/XJS, JS/TS/JSX/TSX, Java/Kotlin, XML/SQL, Vue/Svelte, C#/Python/Go, 설정·텍스트·문서 등 확장자를 읽습니다. 지원 목록은 `src/core/search.cjs`의 `EXTENSIONS`에 있습니다.
- 의존성·빌드·도구 폴더와 바이너리·비밀설정·잠금 파일, 심볼릭 링크, 개별 4MB 초과 파일은 제외하며 내역을 표시합니다. 2026-10-16 김기덕: `clx-build`, `webapps`, `outputs`, `work`, `jsdocs` 하위의 생성·배포본도 기본 제외합니다. 이 폴더 자체를 별도 등록 루트로 선택하면 그 내부는 검색할 수 있습니다. 숨김 폴더도 명시적 제외 대상이 아니면 순회합니다. 등록한 루트 밖 파일은 읽지 않습니다.
- 최대 75,000개 파일, 색인 항목 3,000,000개 제한이 있으며 초과 시 범위 조정을 요청합니다. AI에는 관련 소스 최대 40개·총 240,000자를 발췌해 전송합니다. 파일 뒤쪽의 중요한 일치 줄부터 발췌하고 전체가 아닌 경우 표시합니다.
- 결과에 **코드 처리 흐름**과 **오류 해결 절차**를 추가했습니다. 재현 조건 → 원인 위치 확인 → 수정 대상·내용 → 영향 범위 → 회귀 테스트를 근거 파일·줄과 함께 제안합니다.

## AI 계정과 데이터

- OpenAI·Anthropic/Claude·Google/Gemini·OpenAI 호환 API를 지원합니다. API 계정은 **API 키 방식**으로 연결합니다. 웹 구독 계정의 로그인 세션 재사용이나 OAuth 로그인 기능은 없습니다.
- 모델 목록은 API 응답의 첫 페이지입니다. 목록에 없는 모델도 직접 입력할 수 있습니다. 요청에 이미지가 있으면 이미지 입력 지원 모델이 필요합니다.
- 선택 요청의 ID·제목·요청내용·이미지와 연결된 소스 발췌를 설정된 API로 전송합니다. 담당자·등록자 필드는 프롬프트에 추가하지 않습니다.
- API 키는 Electron `safeStorage`의 Windows 암호화 기능으로 저장합니다. 제공업체나 API 주소를 바꾸면 새 키를 입력해야 합니다.
- 일반적인 비밀번호·토큰 패턴은 텍스트에서 가리지만 모든 민감 정보를 판별하지는 않습니다. 이미지는 자동 마스킹하지 않습니다.
- 분석은 실행 검증 전의 원인 가설입니다. 인용한 파일·줄이 제공 자료에 있는지 확인하고 없는 인용은 **근거 위치 미확인**으로 표시합니다. 위치 확인이 원인 판단의 정확성을 보증하지는 않습니다.
- API 호출 실패는 오류로 표시합니다. 한 실행 안에서 자동 재시도하지 않으며, 다음 실행 때 실패 항목을 다시 시도합니다.

설정·요청·이미지·결과의 정확한 저장 경로는 설정 화면에 표시됩니다(일반 패키지의 기본값은 `%APPDATA%/PMS Manager`, 개발 실행은 `.local-data`). 2026-10-16 김기덕: 전체 목록 수집이 정상 종료되면 현재 PMS 조회 목록에 없는 로컬 요청과 그 분석·대화·메모를 제거합니다. 검색조건으로 제외된 요청도 제거 대상입니다. 빈 조회가 확인되면 로컬 목록도 비웁니다. 조회 실패·취소 시 일괄 제거하지 않습니다. 이번에 분석 대상이 된 요청만 자동 선택됩니다. 남아 있는 요청의 이전 분석은 요청별 5개까지 보관합니다.

## 수집 범위와 한계

- 한 번에 최대 500건. 현재 선택된 단위시스템의 조회 목록만 수집합니다. 검색조건 변경과 다른 단위시스템 선택은 사용자가 합니다.
- 실제 PMS DOM과 Smart Editor 중첩 프레임에 맞췄습니다. 화면 구조가 바뀌면 `src/pms/page.cjs`를 조정해야 할 수 있습니다.
- 전체 건수와 읽은 건수가 다르면 전체 수집 성공으로 처리하지 않습니다. 상세 요청ID와 본문 갱신을 확인하지 못한 요청은 실패로 남깁니다.
- 요청내용 편집기에 포함된 이미지를 읽습니다. 별도 첨부파일 목록·PDF·문서 파일은 현재 수집하지 않습니다. 요청당 이미지 최대 12개·개별 8MB이며 누락·실패를 표시합니다. API 전송은 요청당 최대 19MB입니다.
- base64 이미지와 PMS 동일 출처 이미지를 지원합니다. 외부 출처 이미지·리다이렉트는 자동으로 따라가지 않습니다.
- 수집·분석을 중지하면 이미 저장한 개별 요청과 결과를 유지합니다. PMS 목록 밖 요청의 일괄 정리는 전체 수집이 정상 종료됐을 때 적용합니다.

## 개발 및 검증

Node.js 22.12 이상과 pnpm을 사용합니다.

```powershell
pnpm install
node node_modules/electron/install.js
pnpm test
pnpm start
pnpm dist
```

`node test/preview-server.cjs`는 127.0.0.1:4179에 가상 데이터만 표시하는 화면 검증 도구입니다. 실행 파일에는 포함되지 않습니다.

자동 테스트는 ID·소스 연결, 중복·누락, 자료 변경 이력, 그리드·편집기 수집, 공급자별 이미지 요청, API 오류, 인용 위치와 UI 표시를 검증합니다. API는 가짜 응답으로 검증하며 실사용 키나 실제 프로젝트 소스는 사용하지 않습니다.

개발 앱을 `PMS_SMOKE_TEST=1`로 실행하면 숨김 창에서 UI 로딩·IPC·Node 격리·Windows 키 암호화를 검사합니다. 앱 전용 PMS 창의 실제 로그인 후 일괄 수집과 실계정 AI 호출은 사용자 설정 후 추가 확인이 필요합니다.
